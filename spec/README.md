# Схема базы протоколов

`protocols-database.json`:

```jsonc
{
  "protocols": [           // 178 записей, ключ — protocol_id (= id= из базы ЭБУ)
    {
      "protocol_id": 0,
      "vmt": "0x00621174",          // адрес таблицы методов в оригинале (для сверки)
      "constructor": "sub_43D5B0",  // функция-фабрика класса
      "primitives": [               // 7 примитивов, в порядке применения
        {
          "offset": 8,              // смещение в VMT
          "role": "init/write-setup",
          "function": "sub_43ED70", // функция оригинала
          "ea": "0x0043ED70",
          "nframes": 8              // сколько кадров шлёт шаг
        }
      ],
      "frame_count": 25,
      "ecu_profiles": [             // какие марки/модели идут через этот протокол
        { "profile": "BMW330D", "apps": ["BMW Serie 3 (E46) 3.0 D ..."], "notes": [] }
      ]
    }
  ],

  "functions": {            // кадры хранятся один раз, ключ — имя функции
    "sub_43ED70": {
      "ea": "0x0043ED70",
      "frames": [
        {
          "send_index": 0,     // порядковый номер отправки внутри шага
          "send_addr": "0x0043EF9F",
          "base": -100,        // смещение буфера на стеке (диагностика)
          "len": 6,
          "bytes": [null, null, null, 1, 162, 0],  // null = вычисляется в рантайме
          "known": 3           // сколько байт известно
        }
      ]
    }
  },

  "profile_table": [ ... ],  // 320 профилей ЭБУ как в исходной базе
  "informazioni":  [ ... ]   // 50 записей таблицы идентификации ЭБУ
}
```

`null` в `bytes` — байт, который оригинал вычисляет на ходу: адрес памяти,
ответ seed/key, счётчик. Эти байты нужно восстановить по псевдокоду
соответствующей функции (см. `docs/HANDOFF.md`).

`ecu-profiles.json` — плоский список профилей: `profile`, `ids`, `notes`, `apps`.
Один профиль может встречаться дважды (он есть и в `auto.dll`, и в `auto2.dll`).
