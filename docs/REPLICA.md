# Реплика загрузчика EOBD1260

Собственный загрузчик под обычный K-line адаптер на чипе FTDI. Работает
**напрямую через D2XX, без донгла и без оригинального ПО** — протоколы взяты из
`05-spec/protocols-database.json` (извлечены статическим анализом `EOBD1260.exe`).

## Состав

```
src/ftdi_d2xx.py   транспорт: D2XX через ctypes, K/L-линия на RTS/DTR, чексуммы
src/loader.py      база протоколов + K-line клиент + CLI
```

Зависимостей нет — только стандартный CPython (ctypes) и `ftd2xx.dll`
(лежит в корне пакета, либо берётся установленный в системе).

## Быстрый старт

```bash
cd src

# найти адаптер
python ftdi_d2xx.py
#   FTDI devices: ['FT232R USB UART']

# все протоколы
python loader.py protocols

# какие id у BMW Siemens
python loader.py protocols --profile bmwms4

# что именно шлёт протокол (без железа)
python loader.py show 0
python loader.py show 16

# прогон шага протокола по кабелю (--live = реальная передача)
python loader.py probe 0 --step seed-key            # dry run
python loader.py probe 0 --step seed-key --live --baud 10400
```

## Как это устроено

Оригинал общается с кабелем только через `ftd2xx.dll` (13 функций D2XX), причём
`FT_SetBitMode` не используется: уровни K- и L-линии формируются линиями
**RTS/DTR**. Отсюда два режима, которые реализует `ftdi_d2xx.py`:

- `send_5baud(addr)` — медленная инициализация ISO 14230: старт-бит, 8 бит
  LSB-first, стоп-бит, по 200 мс на бит;
- `k_line_pulse(level, sec)` — импульсы пробуждения для быстрой инициализации.

Протоколы описаны как последовательности шагов. У каждого класса ЭБУ семь
примитивов (смещения VMT `+8…+32`):

| Смещение | Роль |
|---|---|
| `+8` | init / setup записи |
| `+12` | erase |
| `+16` | запись блока |
| `+20` | close write |
| `+24`, `+28` | вспомогательные |
| `+32` | seed-key (доступ) |

Кадры в базе даны шаблонами: константные байты — как есть, рантайм-байты
(адреса, seed/key, счётчики) — `null`. `Frame.render(...)` отказывается
отправлять кадр с незаполненной дырой, чтобы нельзя было случайно послать мусор.

## Пример: BMW DDE4.0 (id=0)

```
seed-key  27 01                  запрос seed
seed-key  27 02 42 4D 57 17      ключ "BMW" + 0x17   <- жёстко прошит в оригинале
erase     09 31 02 08 .. 06 ..
write     B8 12 F1 09 34 68 00 00 06 00 00 C0 00 AF
close     B8 12 F1 03 30 EB 01 82
```

## Пример: Fiat ME7.3H4 (id=16) — короткие кадры (байт длины + SID)

```
02 1A 98 00 / 02 1A 99 00 / 02 1A 91 00 / 02 1A 94 00   init (sub_49B700)
08 34 -- 40 -- 80 07 C0                                  заголовок блока записи
06 -- 56 29 2D BF 6F                                     seed-key (ключ вычисляется)
```

Канонический KWP2000 (`82 12 F1 10 85 1A`) принадлежит дизельным EDC15-протоколам
(id 19, 26, 49, …) — см. `docs/PROTOKOLY.md`; у id=16 заголовка `82 12 F1` нет.

## Порядок ввода в эксплуатацию

Опасные шаги (erase/write) **не выполняются**, пока протокол не проверен на
стенде. Рекомендуемый порядок:

1. **read-only**: инициализация + идентификация ЭБУ, сверить ответы с оригиналом;
2. **идемпотентная запись** в заведомо пустую область (`0xFF`), прочитать назад;
3. полный цикл с бэкапом и восстановлением;
4. acceptance-лог (хеш образа) сохранить в проект.

Запись и стирание — **только на стендовом ЭБУ** (12 В, K-line, масса), никогда
на машине без явного согласия владельца.
